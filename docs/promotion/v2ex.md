# V2EX 发布帖（分享创造节点）

**标题：**
[开源] 我评测了 119 个真实 MCP 服务器，55% 根本没法用——做了个"质检局"告诉大家真相

**正文：**

各位好，分享一个最近全职在做的开源项目 TrustLens（智码星出品）。

背景：MCP 生态现在 6 万+ 公共服务器，但没有任何质量信号——研究显示 66% 有安全问题。装服务器全靠盲选。

我从 npm/PyPI 抓了 122 个**真实发布的** MCP 服务器，在隔离、无凭证环境自动化评测了 119 个。结果：

| 等级 | 数量 | 占比 |
|---|---|---|
| A | 9 | 8% |
| B | 12 | 10% |
| C | 25 | 21% |
| D | 7 | 6% |
| F | 66 | **55%** |

**超过一半的公共 MCP 服务器，按文档 `npx -y <pkg>` 装完、不配任何凭证，90 秒内连协议握手都完不成。** 失败原因：启动挂起 55 个、缺 API key 直接崩 7 个、SDK 兼容性崩溃 3 个（官方 Python 服务器因为 McpError→MCPError 改名启动即崩）。

也有好消息：ref-tools-mcp、duckduckgo-search、ifconfig-mcp 拿到 A 级甚至满分——"热门≠靠谱，冷门≠不可用"。

TrustLens 干的就是质检局的事：沙箱部署 → 握手 → 安全扫描（提示注入/数据外发/硬编码凭证）→ 真实探针调用 → 多模型兼容 → 0-100 信任分。**所有评测数据以 JSON 提交在仓库，git 历史即审计日志。**

排行榜（119 个，支持搜索/筛选/排序/分页，CI 每周自动更新）：https://trustlens.icodestar.net/
仓库：https://github.com/hyqzz/trustlens （Apache-2.0，零依赖 Python）

真心求拍砖：
1. 你装 MCP 前会查这种评分吗？
2. 我们"90 秒握手超时"的开箱即用标准，合理吗？
3. 权重（功能35/可靠25/安全25/兼容15）该调整吗？

**发布节点**：分享创造；时间：工作日早 10 点或晚 8 点。
