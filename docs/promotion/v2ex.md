# V2EX 发布帖（分享创造节点）

**标题：**
[开源] 我评测了 112 个去重的真实 MCP 服务器，60% 根本没法用——做了个"质检局"告诉大家真相

**正文：**

各位好，分享一个最近全职在做的开源项目 TrustLens（智码星出品）。

背景：MCP 生态现在 6 万+ 公共服务器，但没有任何质量信号——研究显示 66% 有安全问题。装服务器全靠盲选。

我从 npm/PyPI 抓取真实发布的 MCP 服务器，去除同一包的重复条目、3 个因会硬挂起评测进程暂缓、内置自检桩不列入，最终榜单 **112 个不同的真实服务器**。在隔离、无凭证环境自动化评测，结果：

| 等级 | 数量 | 占比 |
|---|---|---|
| A | 8 | 7% |
| B | 13 | 12% |
| C | 21 | 19% |
| D | 3 | 3% |
| F | 67 | **60%** |

**六成公共 MCP 服务器，按文档 `npx -y <pkg>` 装完、不配任何凭证，90 秒内连协议握手都完不成。** 失败原因（按 stderr 审计）：启动即崩溃/进程退出 49 个、缺 API key 直接崩 14 个、包解析/兼容问题 2 个、真·挂起 1 个。

**"热门≠靠谱"是反直觉的常态**：唯一满分是名不见经传的 ifconfig-mcp（100 分），A 级一共只有 8 个；连广受欢迎的官方 filesystem 都只有 C 级（70 分）、网红 desktop-commander 只有 C 级（72 分）——GitHub 星标数说明不了任何可靠性问题。

TrustLens 干的就是质检局的事：沙箱部署 → 握手 → 安全扫描（提示注入/数据外发/硬编码凭证）→ **智能探针**（用 DeepSeek-V4 Flash 按每个工具的真实场景生成调用参数，经安全护栏清洗后实测，功能维度反映真实可用性）→ DeepSeek 真实模型工具调用 → 0-100 信任分。**所有评测数据以 JSON 提交在仓库，git 历史即审计日志。**

排行榜（112 个，支持搜索/筛选/排序/分页，CI 每周自动更新）：https://trustlens.icodestar.net/
仓库：https://github.com/hyqzz/trustlens （Apache-2.0，零依赖 Python）

真心求拍砖：
1. 你装 MCP 前会查这种评分吗？
2. 我们"90 秒握手超时"的开箱即用标准，合理吗？需要配置的服务器该给部分分吗？
3. 权重（功能35/可靠25/安全25/兼容15）该调整吗？
