# V2EX 发布帖（分享创造节点）

**标题：**
[开源] 我做了个 MCP 服务器的"质检局"，实测 12 个：官方 Python 系全军覆没

**正文：**

各位好，分享一个最近全职在做的开源项目 TrustLens。

背景：MCP 生态现在 6 万+ 公共服务器，但没有任何质量信号——研究显示 66% 有安全问题。装服务器全靠盲选。

TrustLens 的做法像质检局：沙箱跑起来 → 协议握手 → 静态安全扫描（提示注入/数据外发/硬编码凭证）→ 真实探针调用（延迟+失败率）→ 多模型兼容性 → 输出 0–100 信任分。评测数据全部以 JSON 提交在仓库，可审计。

第一批实测结果比预期还糟：
- 官方归档的 4 个 Python 服务器（time/fetch/git/sqlite）全部起不来（SDK 把 McpError 改名成 MCPError，服务器没跟上）
- 官方 filesystem：握手正常，但 80% 探针调用报错
- 社区热门的 desktop-commander：D 级
- 也有好消息：官方 memory 91 分

排行榜（中英双语，CI 每周自动更新）：https://trustlens.icodestar.net/
仓库：https://github.com/hyqzz/trustlens （Apache-2.0，零依赖 Python）

真心求拍砖：
1. 你装 MCP 前会查这种评分吗？
2. 下一批测哪些？
3. 评分权重（功能35/可靠25/安全25/兼容15）合理吗？
