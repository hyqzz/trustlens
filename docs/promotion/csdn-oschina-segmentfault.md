## OSCHINA（开源中国）

**标题：**
开源项目 TrustLens：把 MCP 服务器当产品来质检，实测 112 个、约六成无法使用

**正文**：用掘金文精简版（去掉三·五节"为什么用真实模型测工具调用"以外的广告感），重点讲：
- 为什么做（生态无质量信号，6 万+ 服务器，66% 有安全问题）
- 怎么做的（隔离沙箱 + 零凭证 + 90 秒握手 + DeepSeek 智能探针 + git 即审计日志）
- 数据公开透明（JSON 全提交，周更自动发布）

**OSCHINA 注意**：开源社区更看重"项目本身"。正文末尾强化：
- Apache-2.0、零第三方依赖 Python、CI 每周自动评测
- 开源协作入口（issue 提测新服务器、PR 修扫描规则）
- 不放任何营销语气，纯工程叙事

## SegmentFault

**标题：**
MCP 服务器质量基准：一个 0–100 信任分是怎么算出来的（附 112 个实测结果）

**正文**：以"方法论"为主线，突出技术深度：
- 信任分四维度：功能 35 / 可靠 25 / 安全 25 / 模型调用 15，为什么这么配
- 90 秒握手超时的取舍；防拖垮护栏（同一服务器连续 2 次超时即跳过）
- 智能探针的生成与清洗（DeepSeek-V4 Flash 生成参数 → 正则安全护栏：破坏性/注入→跳过，凭证→占位符，内网→example.com，敏感路径→探针临时文件）
- 安全维度边界声明（静态文本扫描，非运行时检测，"安全满分"≠"已证实安全"）

**SegmentFault 注意**：读者偏后端/工程师，喜欢"为什么"。把五（接下来做什么）里"行为可信/交易可信"的三级火箭讲透，强调这是长期项目。
