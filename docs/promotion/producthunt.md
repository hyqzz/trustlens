## 制作者介绍（Maker Comment，launch 前写好）

Hi everyone! I've been installing MCP servers blind for months — 60k+ servers and the only "signal" is GitHub stars, which say nothing about whether a server boots.

So I built TrustLens: it actually runs each server in a sandbox (zero credentials, 90s handshake, smart probes with realistic args generated by DeepSeek-V4 Flash), and outputs a 0–100 trust score. All evidence is committed to the repo as JSON — git history is the audit log. A trust product has to be transparent itself.

The first real run: **112 distinct npm/PyPI servers → only 7 grade A (6.3%), 68 are F (60.7%)** — they never complete a handshake with the standard `npx -y <pkg>` and no config. Even the official `filesystem` server scores just C (70), and `desktop-commander` sits at C (72).

Leaderboard (bilingual EN/中文, auto-updated weekly by CI): https://trustlens.icodestar.net/en/
Repo (Apache-2.0, zero-dependency Python): https://github.com/hyqzz/trustlens

Honest questions I'd love feedback on:
1. Is the 90s-handshake "out-of-the-box" criterion fair? Should setup-required servers get partial credit?
2. Which servers should the next batch cover?
3. Scoring weights: functionality 35 / reliability 25 / security 25 / compatibility 15 — what would you change?
