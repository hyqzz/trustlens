## 一、一个让人冒冷汗的现状

MCP（Model Context Protocol）发布不到两年，公共服务器已经超过 **6 万个**。但：

- 跨注册表安全研究显示 **66% 的服务器存在安全问题**
- **88% 的企业 Agent 试点死在上生产之前**——不是模型不行，是没人敢保证工具靠谱
- 你装任何一个 MCP Server 之前，没有任何地方能查到"它到底能不能用、安不安全"

这个生态有应用商店，但没有大众点评；有成千上万的商品，但没有质检局。

## 二、第一批实测数据：官方 Python 系全军覆没

我用自己写的自动化评测引擎实测了 12 个服务器（含 MCP 官方参考实现和生态热门项目）：

| 服务器 | 来源 | 信任分 | 结论 |
|---|---|---|---|
| memory | 官方 | 90.7 (A) | 最健康的官方服务器 |
| context7 | Upstash | 89.3 (B) | 第三方里最强 |
| everything | 官方 | 82.5 (B) | 可用，20% 调用失败 |
| filesystem | 官方 | 68.5 (C) | **80% 探针调用报错** |
| playwright | 微软 | 64.0 (C) | 大厂出品，分数一般 |
| desktop-commander | 社区热门 | 53.2 (D) | 下载量大，质量堪忧 |
| sequential-thinking | 官方 | 47.2 (D) | 官方出品只有 D |
| **time / fetch / git / sqlite** | 官方 | 25.0 (F) | **全部起不来** |

三个让人坐不住的事实：

1. **官方归档的 4 个 Python 服务器（time/fetch/git/sqlite）全部无法启动**——mcp SDK 把 `McpError` 改名为 `MCPError`，官方服务器没跟上，启动即 ImportError。你今天 `uvx mcp-server-time`，它直接崩给你看。
2. **"装得上"和"用得好"是两回事**：filesystem 能握手、能列工具，但真正调用时 80% 的参数组合返回错误。
3. **热门 ≠ 靠谱**：desktop-commander 社区下载量巨大，实测只有 D 级。

README 不会告诉你这些。只有实测数据会。

## 三、TrustLens 是什么

一个开源的 Agent 能力生态信任基准，三样东西：

1. **自动化质检流水线**：隔离环境部署 → 协议握手 → 静态安全扫描（提示注入/数据外发/硬编码凭证）→ 真实试调用 → 多模型兼容性评估 → 0–100 信任分
2. **公开排行榜**：中英双语，每周自动更新，每个服务器一页质检报告
3. **CLI**：装任何 MCP 前扫一下

```bash
python -m trustlens check <server-name>
```

**所有评测数据以 JSON 提交在仓库里，git 历史即审计日志**——做信任生意，自己先得透明。
