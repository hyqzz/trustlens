# 我实测了 6 个 MCP 官方服务器，2 个根本起不来 —— 这就是我做 TrustLens 的原因

> 本文是 TrustLens 项目的启动帖。项目地址：https://github.com/hyqzz/trustlens
> 排行榜（每周自动更新）：https://hyqzz.github.io/trustlens/

## 一、一个让人冒冷汗的现状

MCP（Model Context Protocol）发布不到两年，公共服务器已经超过 **6 万个**。但：

- 跨注册表安全研究显示 **66% 的服务器存在安全问题**
- **88% 的企业 Agent 试点死在上生产之前**——不是模型不行，是没人敢保证工具靠谱
- 你装任何一个 MCP Server 之前，没有任何地方能查到"它到底能不能用、安不安全"

这个生态有应用商店，但没有大众点评；有成千上万的商品，但没有质检局。

## 二、第一批实测数据：连官方服务器都翻车了

TrustLens 的第一批评测对象是 6 个服务器——包括 MCP 官方参考实现。结果：

| 服务器 | 来源 | 信任分 | 结论 |
|---|---|---|---|
| memory | 官方 | 90.7 (A) | 可用 |
| everything | 官方 | 82.5 (B) | 可用，20% 调用失败 |
| filesystem | 官方 | 68.5 (C) | 可用，调用失败率 80% |
| **time** | 官方 | 25.0 (F) | **根本起不来**：与当前 mcp SDK 版本不兼容，`McpError` 已被改名为 `MCPError`，启动即 ImportError |
| **fetch** | 官方 | 25.0 (F) | **同样的病**，同样的 ImportError |
| mock-echo | 内置投毒样例 | 75.0 (B→安全0分) | 安全扫描抓到 4 个投毒行为（提示注入、数据外发） |

注意两点：

1. **两个官方 Python 服务器用当前 SDK 直接起不来**。如果你今天 `uvx mcp-server-time`，它会在你客户的机器上直接崩掉。这种问题，不看评测数据你不会知道——README 里不会写。
2. filesystem 的调用失败率 80%：它能握手、能列工具，但真正调用时大部分参数组合返回错误。**"装得上"和"用得好"是两回事。**

这正是 TrustLens 要测的东西：**不看广告，看疗效。**

## 三、TrustLens 是什么

一个开源的 Agent 能力生态信任基准，三样东西：

1. **自动化质检流水线**：隔离环境部署服务器 → 协议握手 → 静态安全扫描（提示注入/数据外发/硬编码凭证）→ 真实试调用 → 多模型兼容性评估 → 0–100 信任分
2. **公开排行榜**：每周自动更新，每个服务器一页质检报告
3. **CLI**：装任何 MCP 前扫一下

```bash
python -m trustlens check <server-name>
```

**所有评测数据以 JSON 提交在仓库里，git 历史即审计日志**——做信任生意，自己先得透明。
