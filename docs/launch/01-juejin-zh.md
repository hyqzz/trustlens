# 我实测了 112 个去重的真实 MCP 服务器（60% 根本没法用）+ 110 个 Agent Skills —— 我做了一个"质检局"来告诉大家真相

> 项目：https://github.com/hyqzz/trustlens
> 排行榜（MCP 112 个 + Skills 110 个，可搜索/筛选/分页，每周自动更新）：https://trustlens.icodestar.net/

## 一、一个让人冒冷汗的现状

MCP（Model Context Protocol）发布不到两年，公共服务器已经超过 **6 万个**。但：

- 跨注册表安全研究显示 **66% 的服务器存在安全问题**
- **88% 的企业 Agent 试点死在上生产之前**——不是模型不行，是没人敢保证工具靠谱
- 你装任何一个 MCP Server 之前，没有任何地方能查到"它到底能不能用、安不安全"

这个生态有应用商店，但没有大众点评；有成千上万的商品，但没有质检局。

## 二、第一批大规模实测：60% 的服务器装完根本用不了

我从 npm / PyPI 注册表抓取**真实发布的 MCP 服务器**（官方参考实现 + 各来源的社区服务器，全部是真实存在的包），在**隔离环境、无任何 API 凭证**的条件下自动化评测。同一包的重复条目合并、3 个（puppeteer、@enfyra、@mapbox）因会硬挂起评测进程按方法论暂缓、内置自检桩不列入榜单——最终榜单 **112 个不同的真实服务器**：

| 等级 | 数量 | 占比 | 含义 |
|---|---|---|---|
| A | 8 | 7% | 真正开箱即用 |
| B | 13 | 12% | 可用，但有小问题 |
| C | 21 | 19% | 可用性一般 |
| D | 3 | 3% | 风险偏高 |
| **F** | **67** | **60%** | **装完无法使用** |

**六成公共 MCP 服务器，按文档装完、不配任何额外凭证，根本无法启动或完成协议握手。** 失败原因归类（依据每个失败进程的 stderr 审计）：

- **启动即崩溃/进程退出（49 个）**：进程在握手窗口内直接崩退（JS/Python 栈、模块加载失败、端口占用等）
- **缺 API 凭证（14 个）**：文档没说，缺了 key 直接崩
- **包解析/兼容问题（2 个）**：`npx` 连可执行入口都找不到，或依赖装不上
- **真·挂起（1 个）**：进程起来但 90 秒内不响应初始化握手，静默等待未文档化的配置或交互输入

**"热门≠靠谱"是反直觉的常态**：A 级只有 8 个，唯一满分是 `ifconfig-mcp`（100 分，名副其实）；连广受欢迎的官方 `filesystem` 服务器都只有 C 级（70）、网红 `desktop-commander` 只有 C 级（72）——**"下载量大"和"能用"确实是两回事，"冷门"和"靠谱"也是两回事。**

## 三、TrustLens 是什么

一个开源的 Agent 能力生态信任基准，两套评测 + 一个界面：

1. **MCP 服务器质检流水线**：隔离环境部署 → 协议握手 → 静态安全扫描（提示注入/数据外发/硬编码凭证）→ **智能探针实测**（用 DeepSeek-V4 Flash 按每个工具的真实场景生成调用参数，经安全护栏清洗后调用，功能维度反映真实可用性）→ **DeepSeek-V4 Flash 真实工具调用评测** → 0–100 信任分
2. **Agent Skills 评测**：对每个 SKILL.md 做结构质量 + 安全扫描 + 大模型可执行性实测——**已评测 110 个真实 Skill**（来自 GitHub 官方与社区仓库）
3. **公开排行榜**：中英双语，MCP 榜 + Skills 榜，支持搜索、筛选、排序、分页，每周自动更新

```bash
python -m trustlens check <server-name>
```

**所有评测数据以 JSON 提交在仓库里，git 历史即审计日志**——做信任生意，自己先得透明。

## 三·五、为什么要用真实模型测"工具调用"

排行榜上每个 MCP 服务器都有一项"模型工具调用"分——这不是静态估算，是让 **DeepSeek-V4 Flash 真实地读每个工具的定义，判断它会不会调用、能不能构造出合法参数**。生态里没人发布过这份数据：**同一个工具，模型到底能不能真正用起来。**

## 四、方法论（透明声明）

- 评测在**剥离环境变量的隔离进程**中执行，被测服务器**不拿到任何密钥**
- **开箱即用基准**：不填任何配置、不配任何 API key，按 `npx -y <pkg>` 标准方式启动，90 秒内完成握手才算"能启动"
- **防拖垮护栏**：同一服务器连续 2 次工具调用超时，即判定它对真实调用不可用，跳过剩余探针（否则单台病理服务器能拖垮整轮评测）
- **智能探针**：每个工具的真实调用参数由 **DeepSeek-V4 Flash** 按 schema 生成（文件→路径、HTTP→example.com、搜索→关键词），并经**安全护栏**清洗——破坏性/注入值 → 工具整体跳过（不奖不罚），凭证形状 → 改写占位符，内网/本机地址 → 改写 example.com，敏感路径 → 改写为探针临时文件。生成步骤只读已存结果 + 调模型 API，**不执行任何服务器代码**，与评测步骤物理隔离
- 模型工具调用分由 **DeepSeek-V4 Flash**（性价比最高档）真实调用得出
- **安全维度的边界**：静态文本模式扫描，只抓提示注入/数据外发指令/硬编码凭证等明显特征，**无法检出运行时外发等隐蔽行为——"安全满分"≠"已证实安全"**。文中"66% 服务器有安全问题"是外部研究结论，与本榜评分口径不同
- Skills 评估覆盖结构完整性、安全扫描、以及模型可执行性判断
- 评测流水线每周自动复测，结果自动发布
